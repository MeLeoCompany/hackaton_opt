# Эксперимент «Восток», 17 августа 2026 года

Источник заявок — `Обезличивание/Восток Синтетические данные.csv` (66 заявок).
Контрольное распределение служит только для последующего сравнения: назначения
оттуда нельзя подставлять в решатель.

Для первого прогона согласованы допущения: 12 бригад из контрольного списка,
всем назначены общественный транспорт, навыки 1–3 и смена 09:00–23:00.
Это **не фактический табель**. Длительности работ взяты из справочника
`work_type`, а не из CSV, где их нет. Исходный офис «Восток» и его демоданные
остаются отдельно.

Исходные адреса не содержат координат. Для однократной подготовки:

```bash
python -m scripts.audit_anonymized
python -m scripts.geocode_east
```

Скрипт записывает кеш в `geocodes.json` и список непроверенных домов в
`review.csv`. В планирование допускаются только координаты со статусом
`exact_house` или проверенные вручную. Повторный запуск использует кеш и не
посылает повторные запросы. Геокодирование выполняется через данные
[OpenStreetMap/Nominatim](https://operations.osmfoundation.org/policies/nominatim/);
адреса и координаты нужно использовать с атрибуцией OpenStreetMap.

Первый проход: 40 из 65 уникальных адресов совпали по номеру дома; оставшиеся
25 координат внесены вручную в `review.csv`. В исходнике есть неполный адрес
«Самаркандский Квартал 137а, д. к5»; его координаты используются как ручная
поправка, но сам адрес нужно уточнить перед оценкой качества маршрутов.

Проверка без записи и повторяемый импорт:

```bash
python -m scripts.import_east
backend/.venv/bin/python -m scripts.import_east --apply
```

Импорт принимает ручные координаты только для адресов из списка проверки,
проверяет их диапазон и создаёт все записи в одной транзакции. Повторный
`--apply` запрещён, чтобы не дублировать заявки. Для локальной БД Compose
используется `localhost:5432`; другой адрес можно передать через
`EAST_DATABASE_DSN`. Связь исходных и новых номеров заявок сохранена в
`import_report.json`.

20 сентября сценарий загружен в офис «Восток — эксперимент 17.08.2026»
(id 4): 66 заявок, 12 бригад. В админском интерфейсе выберите этот офис и
дату 17.08.2026. Контрольные назначения в БД не импортировались.

Типы BK сопоставлены со справочником работ: подключение → 1, дозаказ → 3,
локальная заявка → 4, глобальная проблема → 2. Срочными помечены только
три записи с типом HD «Авария». Это допущение для эксперимента, которое
потребует проверки на реальных правилах диспетчера.

Проверка 20 сентября: день загружается как 66 заявок и 12 бригад. Исходная
полная матрица R5 не успела ответить за 180 секунд; после разбиения на блоки
матрица была рассчитана за 134 секунды. Пробный расчёт без сохранения плана
с одной попыткой уточнения расписания занял 288 секунд и вернул 60 назначенных
заявок на 7 бригад; 6 визитов оставлены неназначенными из-за опоздания по
фактическому расписанию. Штатный режим сохраняет четыре попытки уточнения и
может дать другой результат. План в БД пока не сохранён и не утверждён.
