# frontend

Vue 3 + Vite + Leaflet поверх тайлов OpenStreetMap. Четыре вкладки:

- **Заявки** — рабочее место диспетчера: панель дня, отдельная строка фильтров в шапке
  таблицы — по фильтру на каждую колонку (номер, активность, адрес, координаты, тип работ,
  длительность «от-до», окно «с-по», приоритет, транспорт и сброс), сортировка по клику
  на заголовок, страницы.
  Тип работ подставляет норматив работы на месте и нужный навык — навык отдельно не выбирают.
  Переключатель «Таблица / Карта»: фильтры общие — в таблице они в её шапке, на карте
  над картой стоит та же шапка таблицы без строк — та же сетка колонок, подписи и поля
  (`RequestsFilterControl.vue` — один компонент на оба места), поэтому при переключении
  каждое поле остаётся на своём месте и своей ширины; на карте видны все заявки, прошедшие фильтры, и карточка выбранной точки.
  Двойной клик по строке открывает карту сразу на этой заявке (у исполнителей — так же). Добавление, изменение прямо в строке, удаление, включение и
  выключение для планирования (по одной и для всех показанных).
- **Сравнение планов** — планы дня списком с колонками «А» и «Б»: отмечаете, какие два
  сравнить (один и тот же план в обе колонки не встанет). Ниже метрики с разницей (срочных
  выполнено, всего выполнено, не назначено, исполнителей, пробег, время расчёта; улучшение
  зелёным, ухудшение красным). Клик по номеру плана в шапке метрик открывает его на вкладке
  «Планы» — подробности по заявкам и маршрутам живут там и в сравнении не дублируются.
- **Загрузка CSV** — отдельная вкладка: файл, шаблон, разбор ошибок по строкам и описание
  колонок.
- **Исполнители** — то же для исполнителей: фильтры в шапке таблицы по каждой колонке
  (номер, имя, транспорт, навык, начало смены «с-по», координаты старта), сортировка,
  правка в строке (навыки галочками, от 1 до 3), удаление; на карте — стартовые точки,
  цвет по типу транспорта.
- **Планы** — кнопка «Построить план» открывает окно параметров расчёта (`PlanBuildDialog.vue`):
  поля заполнены значениями по умолчанию, пока это выбор алгоритма — cuOpt или базовый. Ниже таблица планов дня, в строке
  плана — все его характеристики: номер, время расчёта, решатель, назначено, не назначено,
  исполнителей, общий пробег; клик по строке открывает план, кнопка «Удалить» убирает план
  с его назначениями, чтобы пересчитать день заново. У выбранного плана переключатель
  «Маршруты / Карта». Маршруты — таблицей, строка на бригаду (транспорт, заявок, пробег,
  время в пути, визиты по порядку) с фильтрами по всем колонкам в шапке. На карте — маршрут
  каждого исполнителя своим цветом, серые точки неназначенных заявок и рядом карточки
  маршрутов с общим полем поиска. Клик по маршруту показывает на карте только его,
  повторный клик возвращает все. Неназначенные заявки — таблицей с причиной.
  При fallback пробег в списке помечается знаком `≈`, чтобы оценка по прямой не выглядела
  как точный результат Valhalla.
- **Маршруты (стенд)** — кликаете точки на карте, получаете маршрут.

Время везде московское. Открытая вкладка и выбранный день запоминаются в браузере —
после обновления страницы диспетчер остаётся там же, где работал.

## Слепок дня

На панели дня во вкладках «Заявки» и «Исполнители», справа, есть две кнопки-значка:
**выгрузить** день в CSV и **загрузить** CSV в текущий день. Что делает кнопка, написано
в подсказке при наведении; выгрузка подсвечивается синим, загрузка — зелёным.

Загрузка кладёт файл копией: время суток сохраняется, даты становятся выбранным днём,
номера новые. Существующие заявки и смены дня не удаляются — они могут быть в планах,
поэтому если день не пустой, интерфейс предупреждает, что записи из файла добавятся
к имеющимся, и спрашивает подтверждение.

## День на форме

День — общий параметр вкладок «Заявки», «Исполнители» и «Планы» (`useSelectedDay.js`),
и на каждой из них стоит одинаковая панель `DayPanel.vue`: календарь, шаг на день назад
и вперёд и сводка по этому дню (сколько заявок, смен, планов). Что именно берётся на день —
в подсказке при наведении. Отдельной кнопки «сегодня» нет: в календаре браузера сегодняшний
день и так выделен, а надпись «сегодня» рядом с выбранной датой сбивает с толку.
Выбранный день один на все вкладки и запоминается в браузере; при первом запуске
открывается ближайший день, на который есть активные заявки.

Заявки и исполнители грузятся с бэкенда на выбранный день (`?plan_date=`), планы —
его же.

## Ввод времени

Окно заявки и смена задаются одним полем дня и двумя полями времени (`DayTimeRange.vue`),
а не двумя полями «дата и время» с прокруткой часов.

Время набирается цифрами, двоеточие поле ставит само (`maskTimeInput` в `utils/moscowTime.js`):
`1845` -> `18:45`, `9` -> `09:`. Неподходящая цифра просто не вводится, поэтому `18:90`
или `24:00` в поле не появятся — проверять и подсвечивать ошибку не нужно. Недобранное
время дополняется нулями при уходе из поля: `18:` -> `18:00` (`completeTime`).

По клику в поле открывается список получасовых значений; он сужается по набранному
(`9` оставит `09:00` и `09:30`), выбор мышью подставляет время целиком.

Если второе время не позже первого, окончание считается следующим днём (ночная смена,
ночное окно) — рядом появляется значок «!», при наведении — дата окончания.

## Координаты мышью

Широта и долгота живут в одной колонке «Координаты»: поля стоят друг над другом, рядом —
кнопка со значком карты (`PointPickerButton.vue`). Значок вместо подписи, чтобы ширина ячейки
не менялась и строка не прыгала. Кнопка открывает окно с картой
(`PointPickerDialog.vue`): клик ставит метку, метку можно перетащить, «Готово» подставляет
широту и долготу в поля с точностью до шести знаков. Поля ввода остаются: координаты
по-прежнему можно вписать руками. Серыми точками на карте выбора показаны остальные заявки
(или старты других бригад) — чтобы было видно, куда ставится новая точка.

## Структура (`src/`)

```
pages/       — RequestsPage, EngineersPage, PlansPage, RouteStandPage (по одной на вкладку)
api/         — httpClient.js (общий клиент и разбор ошибок), requestsApi.js, engineersApi.js,
               referencesApi.js, travelApi.js
components/  — Requests*/Request* и Engineers*/Engineer*: таблица, ячейки правки, фильтры,
               карта, карточка; RequestsCsvImport, RequestsPagination; Route* — стенд маршрутов
composables/ — use*Table (загрузка и изменение данных), use*View (фильтры, сортировка, выбор),
               useMessages (ошибки и всплывающие уведомления), useRoutePlanner (стенд)
styles/      — common.css: общие стили всех вкладок (поля, кнопки, фильтры, таблицы,
               переключатели, карта, карточки, уведомления)
utils/       — moscowTime.js (UTC <-> Москва), referenceNames.js (названия из справочников),
               transportColors.js (цвета транспорта), polyline.js (декодер линии маршрута)
```

## Запуск

Вместе со всем стеком из корня репозитория: `docker compose up` → http://localhost:5173

Локально (бэкенд должен быть доступен на :8000):

```
npm install
npm run dev
```

Фронт всегда ходит на относительный `/api`, в дев-режиме его проксирует vite
(`vite.config.js`), поэтому CORS в браузере не возникает. Адрес бэкенда задаётся
переменной `VITE_API_TARGET`.

## Что важно знать про отрисовку

- **Геометрия маршрута приходит как encoded polyline с точностью 6 знаков.** У Leaflet и Google
  по умолчанию 5 — если перепутать, координаты уедут в десять раз.
- **Уведомления об успехе всплывают поверх страницы**, а не вставляются над таблицей —
  иначе строки съезжают прямо под курсором.
- **Масштаб карты подгоняется только при смене набора точек** (фильтр, загрузка), а не при
  изменении их свойств — иначе карта прыгает на каждое включение/выключение.
- **Ширины колонок таблиц заданы в `colgroup` при `table-layout: fixed`** — иначе браузер
  пересчитывает их по содержимому, и колонки разъезжаются при каждой фильтрации и при
  переходе строки в режим правки.

## Просмотр плана

Если Valhalla недоступна при просмотре, приближённый пробег
помечается предупреждением. Маршруты при просмотре рассчитываются заново: снимок защищает
от редактирования заявок и инженеров, но не от обновления дорожных данных Valhalla.

Проверка: `node --test tests/*.test.mjs` и `npm run build`.
