# Локальное развёртывание

Без домена, без сертификата, без настройки: всё поднимается на вашей машине одной командой.
Так проверяют систему перед показом и так же работают на ноутбуке во время разработки.

## Что нужно

| | Минимум | Комфортно |
|---|---|---|
| Docker | Desktop 4.30+ или Docker Engine 26+ | то же |
| Память | 8 ГБ (без общественного транспорта) | 16 ГБ |
| Диск | 20 ГБ | 40 ГБ |
| Видеокарта | не нужна: расчёт пойдёт на OR-Tools | NVIDIA + драйвер для cuOpt |

Видеокарту искать не нужно: скрипт сам смотрит, отдаёт ли docker устройство NVIDIA, и если
нет — снимает требование GPU и пишет, каким решателем будет считать. CUDA на машину ставить
не надо ни в каком случае: она внутри образа бэкенда.

## Запуск

```bash
git clone https://github.com/MeLeoCompany/hackaton_opt.git
cd hackaton_opt
./deploy/local.sh
```

Скрипт поднимает контейнеры, дожидается базы, накатывает миграции, ждёт бэкенд и печатает
адреса. Повторный запуск — обновление: пересобирается только изменившееся.

| Адрес | Что это |
|---|---|
| http://localhost:5173 | Рабочее место диспетчера |
| http://localhost:5175 | Приложение бригады |
| http://localhost:8000/docs | Описание API |

Первый вход — `admin` / `admin`. Пароль администратора в миграциях не хранится: он берётся
из переменной `ADMIN_PASSWORD` и ставится при старте бэкенда. Чтобы задать свой:

```bash
cp .env.example .env     # в корне проекта
$EDITOR .env             # ADMIN_PASSWORD=...
./deploy/local.sh
```

Там же в `.env.example` перечислено остальное, что можно настроить: подпись токенов,
пределы времени расчёта, скорость пешехода. Без файла всё работает на значениях по
умолчанию. Дальше пароль меняется в «Справочники» → «Пользователи», там же заводятся
диспетчеры; бригадам логин и пароль выдаются в «Справочники» → «Бригады».

## Первый запуск долгий

Valhalla скачивает карту Центрального федерального округа (около 877 МБ) и строит из неё
тайлы, после чего R5 вырезает Москву с областью и собирает транспортный граф. Это десятки
минут. Данные остаются в томах docker, поэтому следующие запуски занимают минуту.

Пока маршрутизаторы собираются, система уже работает: интерфейс открывается, справочники
и заявки доступны, а расчёт плана честно отвечает «маршрутизатор ещё не готов».

Если 16 ГБ памяти нет или общественный транспорт не нужен:

```bash
./deploy/local.sh --light
```

Тогда R5 не поднимается: планирование считается по дорогам (Valhalla), пешие и транспортные
плечи не строятся.

## Остановка и сброс

```bash
./deploy/local.sh --stop     # остановить, данные и собранные карты сохранить
./deploy/local.sh --reset    # стереть всё вместе с томами: база, тайлы, граф
./deploy/local.sh --logs     # смотреть логи
```

`--reset` возвращает систему к чистому состоянию: база наполнится демонстрационными данными
заново, а Valhalla и R5 снова будут собирать карты — это опять десятки минут.

## Если что-то не поднялось

```bash
docker compose ps                      # чьё состояние не healthy
docker compose logs backend --tail 50  # что говорит бэкенд
bash db/apply_migrations.sh --status   # какие миграции накачены
```

- **Порт занят** (5173, 5175, 8000, 5432) — освободите его или поменяйте в `docker-compose.yml`.
- **Мало памяти** — в Docker Desktop поднимите лимит или запускайте с `--light`.
- **cuOpt не стартовал** — это нормально без видеокарты NVIDIA: расчёт идёт на OR-Tools,
  в журнале расчётов видно, каким решателем считали.
