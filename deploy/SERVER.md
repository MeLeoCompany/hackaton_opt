# Развёртывание на сервере

Один скрипт разворачивает систему с нуля и он же её обновляет. Запускается с вашей машины,
всё остальное делает сервер сам: забирает код из git, собирает образы и поднимает сервисы.

```bash
cp deploy/deploy.env.example deploy/deploy.env
$EDITOR deploy/deploy.env        # что заполнить — ниже
./deploy/deploy.sh --check       # проверить доступ, ничего не менять
./deploy/deploy.sh               # развернуть или обновить
```

## Что нужно предоставить

Всё это — поля `deploy/deploy.env`. Файл в git не попадает: в нём пароли.

| Поле | Что это | Пример |
|---|---|---|
| `SERVER_HOST` | адрес сервера | `203.0.113.10` |
| `SERVER_USER` | пользователь ssh с правом ставить пакеты | `root` |
| `SERVER_PORT` | порт ssh | `22` |
| `SERVER_SSH_KEY` | приватный ключ для входа | `~/.ssh/id_ed25519` |
| `SERVER_PASSWORD` | пароль, если входим не по ключу (нужен `sshpass`) | |
| `DEPLOY_PATH` | куда положить проект на сервере | `~/routing` |
| `REPO_URL` | откуда сервер берёт код | `https://github.com/…/hackaton_opt.git` |
| `REPO_BRANCH` | какая ветка разворачивается | `main` |
| `GITHUB_TOKEN` | токен GitHub для приватного репозитория (Contents → Read) | `github_pat_…` |
| `DOMAIN` | доменное имя, A-запись которого уже смотрит на `SERVER_HOST` | `routing.example.com` |
| `TLS` | `true` — сертификат Let's Encrypt; `false` — работа по http | `true` |
| `ACME_EMAIL` | почта для писем об истечении сертификата | `ops@example.com` |
| `DB_PASSWORD` | пароль базы, свой | `openssl rand -hex 24` |
| `AUTH_SECRET` | подпись токенов входа, своя | `openssl rand -hex 24` |
| `TRANSIT` | поднимать ли общественный транспорт (R5) | `true` |
| `GPU` | есть ли видеокарта NVIDIA для cuOpt | `true` |
| `INSTALL_DOCKER` | поставить docker и nvidia-toolkit, если их нет | `true` |

## Доступ сервера к приватному репозиторию

Сервер забирает код сам, поэтому ему нужен доступ. Положите в `deploy.env` токен GitHub:

```
GITHUB_TOKEN=github_pat_...
```

Fine-grained токен на этот репозиторий, прав достаточно **Contents → Read**. На сервере
токен не сохраняется: он передаётся только на время git-команды и стирается сразу после,
в `.git/config` остаётся чистый адрес без него.

Для публичного репозитория токен не нужен — оставьте поле пустым.

## Сервер с видеокартой: что нужно поставить заранее

Путаница частая, поэтому по пунктам. Для расчёта на видеокарте нужны **две разные** вещи:

1. **Драйвер NVIDIA на самом сервере** — ставит администратор, нужна перезагрузка.
   На Ubuntu достаточно `ubuntu-drivers install`, проверка — `nvidia-smi`.
2. **nvidia-container-toolkit** — прокидывает видеокарту внутрь контейнера.
   Его ставит `deploy.sh` сам, если видит драйвер.

**CUDA Toolkit с сайта NVIDIA ставить не нужно.** CUDA и сам cuOpt уже лежат внутри образа
бэкенда — на сервере нужен только драйвер, который эту CUDA обслужит.

Скрипт не молчит и не падает, если чего-то нет: он проверяет, видит ли контейнер
видеокарту на самом деле (`docker run --gpus all … nvidia-smi`), и при неудаче честно
пишет, чего не хватает, и разворачивает систему без GPU — расчёт пойдёт на OR-Tools.
Когда драйвер поставите, просто запустите `./deploy/deploy.sh` ещё раз.

## Требования к серверу

| | С транспортом и GPU | Без транспорта |
|---|---|---|
| Ядра | 8 | 4 |
| Память | 24 ГБ | 8 ГБ |
| Диск | 60 ГБ | 30 ГБ |
| Видеокарта | NVIDIA с драйвером ≥ 535 | не нужна |
| Наружу | порты 80 и 443 | 80 |

Ubuntu 22.04/24.04 или Debian 12. Наружу смотрит только nginx: база, бэкенд, Valhalla и R5
доступны лишь внутри docker-сети.

## Что делает скрипт

1. проверяет доступ по ssh, ставит docker (и nvidia-container-toolkit, если нужен GPU);
2. клонирует репозиторий в `DEPLOY_PATH`, при повторном запуске — подтягивает ветку;
3. пишет `.env` на сервере из ваших настроек, правами `600`;
4. **пересобирает только то, что изменилось** в пришедших коммитах: правки бэкенда —
   образ бэкенда, правки интерфейсов — образ nginx со статикой, правки R5 — его образ.
   Нет новых коммитов — ничего не пересобирается;
5. накатывает миграции базы (`db/apply_migrations.sh`, идемпотентно);
6. выпускает сертификат, если его ещё нет, и поднимает обновлятор — дальше он продлевает
   сам раз в 12 часов;
7. ждёт, пока бэкенд станет здоровым, и печатает адреса.

Первый запуск долгий: Valhalla качает карту ЦФО и строит тайлы, R5 собирает граф. Это
десятки минут, дальше данные живут в томах и обновления их не трогают.

## Обновление

```bash
./deploy/deploy.sh            # подтянуть ветку и пересобрать изменившееся
./deploy/deploy.sh --force    # пересобрать всё заново, если кэш врёт
./deploy/deploy.sh --status   # что запущено
./deploy/deploy.sh --logs     # хвост логов
```

## Автоматическое обновление по push

В `.github/workflows/deploy.yml` лежит готовый шаг: по push в ветку он прогоняет тесты и
запускает тот же `deploy.sh`. Чтобы он заработал, заведите в настройках репозитория
(Settings → Secrets and variables → Actions) секрет `DEPLOY_ENV` — целиком содержимое
вашего `deploy/deploy.env`. Пока секрета нет, шаг просто пропускается.

## Если что-то пошло не так

Каждый запуск пишет журнал в `deploy/logs/deploy-<дата>-<время>.log` и печатает шаги
по порядку. Если сорвалось, последняя строка прямо говорит, где именно:

```
== [4] Собираю и поднимаю · 15:47:39
...
СОРВАЛОСЬ на шаге [4] «Собираю и поднимаю», код выхода 1
Журнал запуска: deploy/logs/deploy-20260927-154739.log
Что было на сервере: ./deploy/deploy.sh --logs
```

Шаги идут так: 1 подготовка сервера, 2 получение кода, 3 настройки, 4 сборка и подъём,
5 миграции базы, 6 сертификат, 7 проверка. По номеру сразу видно, до чего дошли.

```bash
./deploy/deploy.sh --status
./deploy/deploy.sh --logs
```

- **Сертификат не выпустился** — проверьте, что A-запись домена смотрит на сервер и порт 80
  открыт: Let's Encrypt проверяет владение именно по http. До выпуска сайт работает по http,
  после выпуска nginx сам переключится на https, перезапуск не нужен.
- **Бэкенд не стал healthy** — `docker compose logs backend`. Частая причина: не задан
  `AUTH_SECRET` или `DB_PASSWORD` в `deploy.env`.
- **cuOpt не поднялся** — на сервере нет видеокарты или драйвера: поставьте `GPU=false`,
  расчёт пойдёт на OR-Tools.
- **Кончилось место** — `docker system prune -f` уберёт старые образы; тома с картами и
  базой при этом не трогаются.
