# Развёртывание

Два способа поднять систему. Выбирайте по тому, нужен ли доступ снаружи.

| | Локально | На сервере |
|---|---|---|
| Команда | `./deploy/local.sh` | `./deploy/deploy.sh` |
| Что настраивать | ничего | `deploy/deploy.env` |
| Домен и сертификат | не нужны | нужны (или `TLS=false`) |
| Как открывается | `http://localhost:5173` | `https://ваш-домен` |
| Инструкция | [LOCAL.md](LOCAL.md) | [SERVER.md](SERVER.md) |

## Что здесь лежит

| Файл | Зачем |
|---|---|
| `deploy.env.example` | все настройки сервера: адрес, доступ, домен, пароли. Копируется в `deploy.env` |
| `deploy.sh` | развёртывание и обновление сервера по ssh; он же шаг CD |
| `local.sh` | локальный запуск одной командой |
| `compose.server.yml` | серверный режим поверх базового `docker-compose.yml` |
| `compose.gpu.yml` | видеокарта NVIDIA для решателя cuOpt |
| `nginx/` | образ с собранными интерфейсами: отдаёт статику, проксирует API, держит TLS |
| `logs/` | журналы запусков `deploy.sh`: по ним видно, на каком шаге сорвалось (в git не идут) |

## Как это устроено

Базовый `docker-compose.yml` в корне — девелоперский: дев-серверы vite, бэкенд с
перезагрузкой по изменению файлов, порты наружу. Локальный запуск берёт его как есть.

Сервер — тот же compose плюс оверлей `compose.server.yml`, который меняет ровно то, что
отличает боевой контур от рабочего стола:

- наружу смотрит только nginx (80 и 443), остальные порты закрыты;
- интерфейсы собраны в статику и лежат внутри nginx, дев-серверы не запускаются;
- бэкенд работает из образа, без перезагрузки и без проброса исходников;
- пароль базы и подпись токенов берутся из ваших настроек, а не из значений по умолчанию;
- рядом поднимается обновлятор сертификата.

Обновление инкрементальное: сервер подтягивает ветку и пересобирает только те образы, чьи
файлы поменялись в пришедших коммитах. База, карты Valhalla и граф R5 живут в томах docker
и обновление их не трогает.
